# 엔트리 자동채점

실제 EntryJS 엔진에서 `.ent` 파일을 실행하는 Mac 데스크톱 채점기입니다. 블록 코드를 다른 언어로 번역하거나 정답을 추측하지 않습니다.

## 사용

`dist/엔트리 자동채점.app`을 더블클릭합니다.

1. **학생 제출 폴더**를 선택합니다.
2. **테스트 케이스 폴더**를 선택합니다.
3. **채점 시작**을 누릅니다.
4. 화면에서 결과를 확인하고 **Excel로 저장**을 누릅니다.

Excel에는 `학생별 결과`, `테스트별 상세`, `실행 정보` 시트가 생성됩니다. 배점 기준은 아직 지정되지 않았으므로 통과 수·오답 수를 제공하며 점수를 임의로 부여하지 않습니다. CSV 저장도 가능합니다. 중단했을 때는 완료된 테스트만 저장하고 실행 정보에 중단 사실을 표시합니다.

### 폴더 구성

한 문제만 채점할 때:

```
학생제출/                    테스트케이스/
  20401_학생이름_문제1.ent      input1.txt
  20402_학생이름_문제1.ent      output1.txt
                              input2.txt
                              output2.txt
```

여러 문제를 함께 채점할 때는 양쪽에 같은 이름의 하위 폴더를 만듭니다.

```
학생제출/                    테스트케이스/
  문제1/*.ent                 문제1/input1.txt, output1.txt, ...
  문제2/*.ent                 문제2/input1.txt, output1.txt, ...
  문제3/*.ent                 문제3/input1.txt, output1.txt, ...
```

### 입력과 정답

UTF-8 텍스트를 사용합니다. `inputN.txt`의 한 줄이 `묻고 대답 기다리기`의 답변 하나입니다. 입력창이 실제로 열릴 때 다음 줄을 제출합니다. 숫자 0도 입력됩니다. 현재 엔트리 입력창이 완료 처리하지 않는 빈 문자열은 지원하지 않으며, 중간 빈 줄이 있으면 시작 전에 알려줍니다. 파일 끝의 한 번의 개행은 빈 답변으로 간주하지 않습니다. 입력이 전혀 없는 문제는 빈 input 파일을 사용합니다.

`outputN.txt`에는 입력 후 말풍선에 포함되어야 하는 **정답 문자열**을 적습니다. 예를 들어 정답이 `120`이면 `정답은 120입니다`도 통과합니다. 앞뒤 공백·줄바꿈은 무시하고, 내부 문자열은 그대로 포함되어야 합니다. 인사말 등 앞선 말풍선, 질문 말풍선, 생각하기는 비교하지 않습니다. 숫자 경계를 따로 구분하지 않으므로 `1200`에도 `120`이 포함된 것으로 판정합니다.

### 판정

- 통과 / 오답: 정상 종료 후 입력 후 말풍선 비교
- 입력 부족: 입력 파일의 줄을 모두 소비한 뒤 추가 답변 요청
- 입력 남음: 프로그램이 종료됐는데 사용하지 않은 답변이 있음
- 출력 없음: 말하기 말풍선이 없음
- 시간 초과: 제한 시간까지 프로그램이 종료되지 않음
- 실행 오류: 프로젝트 손상, 엔트리 블록 실행 오류, 불러오기 실패 등

기본 제한 시간은 테스트당 30초입니다. 말하기 대기 시간도 실제로 기다립니다. 영원히 반복하면서 결과만 표시하는 프로젝트는 종료되지 않으므로 시간 초과입니다. 각 테스트는 별도의 새 브라우저 실행 환경을 사용하여 변수·리스트·함수 상태를 격리합니다. 프로젝트 로딩에는 별도의 여유 시간을 둡니다.

키보드/마우스 이벤트, 하드웨어, AI, 외부 서버 입력을 요구하는 문제는 이 입력 파일 채점 방식의 대상이 아닙니다. 실행 환경에서 외부 네트워크·장치 권한은 차단합니다. 원본 제출물은 읽기만 하며 수정하거나 서버에 업로드하지 않습니다.

## Windows 빌드

**이 저장소만 받으면 됩니다.** 검증한 EntryJS 브라우저 실행 자산은 `vendor/entry-runtime.tar.gz`에 포함되어 있습니다. 다른 엔트리 소스를 따로 받거나 빌드할 필요가 없습니다.

Windows 10/11 64비트에 Node.js 22.13 이상과 Git을 설치한 뒤 PowerShell에서 실행합니다.

```powershell
git clone https://github.com/LHOIKTN/entry-grader.git
cd entry-grader
npm ci
npm run prepare:runtime
npm run build:win
```

일반적인 x64 PC에서는 `dist/entry-grader-win-x64/EntryGrader.exe`를 실행합니다. 다른 PC로 옮길 때는 **entry-grader-win-x64 폴더 전체**를 복사하세요. exe 하나만 옮기면 실행되지 않습니다. 빌드된 앱을 실행하는 PC에는 Node.js나 소스가 필요 없습니다. Windows 설치 프로그램 형태는 아니며, 서명되지 않은 휴대용 실행 폴더입니다.

이미 clone한 폴더에서는 `git pull` 후 나머지 명령을 실행하면 됩니다. Mac의 node_modules나 .app을 Windows로 복사하지 마세요. Windows에서 npm ci를 실행해야 Windows용 Electron이 준비됩니다. 첫 의존성 설치에는 인터넷이 필요하고, 앱 실행·채점은 로컬에서 진행됩니다.

## 개발 및 Mac 빌드

```sh
npm ci
npm run prepare:runtime
npm test
npm run test:engine
npm run test:ui
npm start
npm run build:mac
```

Mac 빌드는 현재 Mac 아키텍처용 `dist/엔트리 자동채점.app`을 만듭니다. 앱에는 엔진과 필요한 라이브러리가 포함되어 있습니다.

엔진 자산을 직접 교체하는 개발자만 다음 명령으로 빌드된 EntryJS 및 설치된 Entry Offline 소스에서 자산을 다시 준비합니다.

```sh
npm run prepare:runtime -- /경로/entryjs /경로/entry-offline
```

`runtime/manifest.json`에 엔진 커밋과 JS의 SHA-256이 기록됩니다. 버전을 교체하면 엔진 테스트도 다시 실행하세요. 실행 규칙은 그대로 두고 말풍선 관찰과 입력 완료 이벤트를 연결합니다.

현재 Mac에서 실제 엔진 실행, 재귀 함수가 있는 제출물, 질문 입력과 입력 후 말풍선 수집, Excel 저장을 검증했습니다. Windows 빌드 스크립트는 추가했지만 실제 Windows에서 실행 검증하지는 않았습니다.

## Git

`node_modules/`, `runtime/`, `dist/`, `.ent`, `.csv`, `submissions/`, `results/`는 Git에서 제외합니다. 실제 학생 이름·명단·제출물·결과 파일을 소스에 추가하지 마세요. `samples/`는 사용법 예시이며 실제 수행평가 정답이 아닙니다.

원격 저장소를 만든 뒤:

```sh
git remote add origin <저장소 주소>
git push -u origin main
```

엔진과 함께 복사되는 서드파티 자산에는 원래 라이선스가 적용됩니다. EntryJS는 Apache-2.0, 이 채점기 코드는 MIT입니다. Electron의 LICENSE와 Chromium 라이선스도 앱에 포함됩니다.

## 입력 후 출력 판정 범위

마지막 답변을 입력창에 제출한 시점부터 프로그램이 정상 종료할 때까지 생성된 말하기 말풍선을 모두 수집합니다. 그중 **하나의 말풍선**에 output 파일의 정답 문자열이 포함되면 통과합니다. 입력 전 및 입력 도중에 나온 말풍선과 질문 말풍선은 제외합니다. 입력이 없는 테스트는 실행 시작부터 검사합니다. 서로 다른 말풍선의 텍스트를 이어 붙여 정답으로 처리하지 않습니다. Excel에는 입력 후 수집한 말풍선을 줄바꿈으로 구분해 기록합니다. 정답이 나타났더라도 실행 오류·시간 초과·입력 부족으로 끝나면 해당 오류 판정을 유지합니다.
